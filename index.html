운영 중 개인 · 풀스택 2026.08 ~ 현재

Tokyo Collective

제가 중고로 판매하는 빈티지 의류를 소개하는 쇼핑몰입니다. 중고 거래 플랫폼 FruitsFamily의 판매자 페이지와 15분마다 자동으로 동기화하고, 구매는 원본 판매 링크로 연결합니다.

사이트 바로가기 ↗ GitHub ↗

주요 기능

  • 쇼핑 상품 목록, 장바구니, 주문 기록. 결제 없이 주문 정보만 저장하고 구매는 원본 링크로 연결
  • 관리자 대시보드 로그인 후 상품 등록·수정·삭제, 주문 확인, 재고 관리
  • 자동 동기화 신규 상품 등록, 품절·재입고 반영, 삭제된 상품 제거, 이름·가격 갱신

기술 스택

Vue 3Vue RouterPiniaViteNode.jsExpressSQLiteTursoVercelGitHub Actionscron-job.orgVitest

역할

기획, 설계, 프론트엔드, 백엔드, 배포, 운영을 혼자 담당했습니다. AI 코딩 도구(Claude Code)로 개발 속도를 높이고, 핵심 로직은 직접 검증했습니다.

  • API는 인증 수준을 세 가지로 나눴습니다: 공개 조회 / 관리자 토큰 / 동기화 전용 시크릿 헤더
  • 환경 변수 하나로 개발은 로컬 SQLite, 운영은 Turso를 쓰도록 전환됩니다
  • master 브랜치에 푸시하면 Vercel이 자동으로 배포합니다
문제

동기화가 한 번 빠지면 이미 팔린 옷이 사이트에 계속 남습니다. 반대로 스크래핑이 중간에 깨지면, 일부만 읽힌 목록 때문에 멀쩡한 상품이 사이트에서 사라질 수 있었습니다.

해결 1

스케줄러 이중화 cron-job.org를 주 경로로, GitHub Actions를 백업으로 두어 한쪽이 빠져도 동기화가 이어지게 했습니다.

해결 2

실패하면 반영하지 않기 스크래핑이 실패하면 변경 사항을 DB에 쓰지 않고 이전 상태를 유지하도록 했습니다.

검증

네트워크와 DB 없이 도는 테스트(Vitest)로 동기화의 핵심 로직을 확인합니다.

  • 실제로 물건을 파는 서비스에는 "잠깐 틀려도 되는 데이터"가 없었습니다. 기능보다 실패했을 때의 동작을 먼저 정하는 습관이 생겼습니다.
  • AI 도구로 개발 속도를 높이되, 스크래핑·동기화·인증처럼 서비스가 의존하는 로직은 직접 읽고 테스트로 확인해야 한다는 것을 배웠습니다.
팀장 4명 · 프론트엔드 2025.09 ~ 2025.12

InfoMate

뉴스 URL을 넣으면 AI가 출처, 편향성, 광고성을 분석해 0~100점의 신뢰도를 알려주는 가짜뉴스 판별 서비스입니다. 팀장으로 4명 팀을 이끌고 프론트엔드를 맡았습니다.

GitHub ↗

팀장으로 한 일

  • 4명의 역할(프론트엔드, 백엔드, 데이터 수집, 협업)을 나눴습니다
  • 프론트·백엔드 주차별 마일스톤을 세우고 Notion 작업 보드로 일정을 관리했습니다
  • 정기 회의를 진행하고 중간·최종 발표를 맡았습니다
  • 막힌 팀원의 파트는 같이 붙어서 해결했습니다. 백엔드 안정화 작업을 함께 진행했습니다

프론트엔드로 한 일

  • API 통신 계층 통신 코드를 services/api.js로 분리하고 API 주소를 환경 변수로 관리
  • 분석 요청 흐름 URL 유효성 검사, API 호출, Postman·CORS 확인을 거친 백엔드 연동
  • 결과 화면 AnalysisResult 컴포넌트 구현
  • 대기 경험 로딩 스피너, 예상 소요 시간, 에러 메시지, 재시도 버튼
Vue 3ViteAxiosNotionDjangoBeautifulSoupPyTorch · KLUE/roberta-smallDocker ComposeNginx

점선 표시는 팀 프로젝트에서 함께 쓴 기술입니다.

문제

분석 한 번에 크롤링과 AI 추론을 차례로 거쳐 응답이 늦었습니다. 기다리는 동안 진행 상황을 알 수 없었고, 지연되면 응답이 오지 않기도 했습니다. 같은 기사도 매번 처음부터 분석했습니다.

프론트

로딩 스피너와 예상 소요 시간을 보여주고, 실패하면 원인별 에러 메시지와 재시도 버튼을 띄웠습니다.

백엔드

팀원과 함께 크롤링·추론에 타임아웃을 걸고, 같은 URL은 결과를 캐싱해 바로 돌려주게 했습니다. 응답 시간을 모니터링하며 추론 속도도 개선했습니다.

결과

응답 시간은 백엔드만의 문제가 아니라, 기다리는 동안 무엇을 보여주는지까지 포함한 문제라는 것을 배웠습니다.

  • 파트를 나눠도 문제는 경계에서 생깁니다. API 요청·응답 형식과 에러 코드를 초기에 백엔드와 합의하고 문서화해 연동을 수월하게 만들었습니다.
  • 팀장의 일은 일을 나누는 것에서 끝나지 않고, 막힌 곳을 먼저 찾아가 같이 푸는 것이라는 걸 배웠습니다.

DED-SCANPATH

  • 사이클 생성·수정·삭제를 Supabase와 연동
  • 오프라인 모드 장비 옆에서 쓰는 도구라 연결이 끊겨도 로컬 스토리지 백업으로 작업이 이어지게 구현
  • NC 코드 할당, 3D 프린팅 코드 생성, 반응형 사이드바
